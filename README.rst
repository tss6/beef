beef device
===========

QEMU PCIe device hello world implementation with a linux kernel driver.

Structure
---------

::

    .
    |--- Makefile
    |--- include             # shared headers
    |--- qemu                # qemu src submodule
     `-- src
         |--- hw             # qemu device implementation
          `-- sw
              |--- kmod      # linux kernel driver
               `-- uspace    # userspace test programs

Overview
--------

``beef`` is a minimal PCIe device implemented in QEMU with a linux kernel
driver. Made with the goal to understand how PCIe devices, DMA and interrupts
work internally.

The device exposes a BAR for MMIO registers, supports 64bit DMA and (depending
on the commit tag) uses either INTx, MSI or MSIx for interrupts. The driver
allocates a DMA buffer, sets the device registers and may issue commands such
as to read or write to the device's internal memory. After that, it waits for
the device to raise a irq to announce completion.

Building
--------

QEMU has the dependencies listed `here
<https://www.qemu.org/docs/master/devel/build-environment.html>`_.

to build qemu::

    make qemu

The kernel module requires the linux headers compatible with the VM you are
going to run with the built QEMU binary. To figure this out, run your VM once,
maybe with::

    make run # update the var VM_IMAGE in root's Makefile

and check ``uname -r``. That is the kernel headers you need. You can install
them in your system (in debian) via::

    sudo apt install linux-headers-$(uname -r)

with the headers, you can build the kernel module::

    make kmod # update the var KDIR in kmod's Makefile to the correct path

I use clangd as my lsp so it is useful to have a ``compile_commands.json`` for
developing as it can then resolve symbols correctly in this weird setup. You
can generate a merged ``compile_commands.json`` (kernel and qemu) with::

    make compile_commands

Notes
-----

- The QEMU source is a git submodule pinned to a specific upstream commit.
  The build system patches it locally at build time, those patches are never
  committed to the QEMU submodule (see ``.gitignore``).

- The first ``make qemu`` will copy ``src/hw/`` into the QEMU source tree,
  patch meson/Kconfig, run configure, and build. On subsequent runs, only
  changed files are compiled (i hope...).

- ``make run`` forwards host port ``2222`` to guest's ``22`` so you can ssh/scp
  into the VM with ``ssh -p 2222 user@localhost`` once it boots. (or ``scp -P
  2222 ...``).

- ``make run`` also creates a `qemu-debug.log` file so that you can see the
  internal logs generated by the device easily. The rest of the logs should
  either appear in the terminal or with ``dmesg`` command (or both).

- The KDIR varible is not just ``/lib/modules/$(shell uname -r)/build`` because
  your VM's kernel may be different from your current system's (my case), so i
  decided to pin it for consistency
